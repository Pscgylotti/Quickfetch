# 0.0.1 资源检查

日期：2026-10-18。Windows 11 x64、.NET 10 Desktop Runtime，本机交互环境。采样脚本为 `scripts/Measure-Idle.ps1`。

## 审查发现

原版本没有周期性磁盘扫描，原隐藏窗口 15 秒采样的 CPU 增量、读写操作及字节数均为 0。主要可优化的路径是启动与目录变化：

- 每次启动重新请求 Shell 图标。
- 任意目录事件都在短暂合并后全目录重扫，并逐项重新读取文件元数据。
- 每次扫描重建 watcher，存在切换窗口内漏接事件的可能。
- 隐藏窗口仍可保留大量 Everything 结果；单实例信号占用一个长期等待的线程池任务。

## 0.0.1 调整

- 启动读取一个打包缓存文件并做一次目录复核，以识别进程未运行时的变化。枚举直接取得时间和大小，避免随后重复逐项 stat。
- 未变的图标从 PNG 缓存恢复；只有变化、新增或 F5 强刷的项才请求 Shell。
- 系统通知 650ms 合并，普通事件只更新该文件，目录移动只处理旧、新子树；通知溢出和手动刷新才全量复核。watcher 在配置不变时持续复用。
- 同一缓存内容不重复写盘，仅保存哈希用于比较。缓存有版本、根目录、递归配置及大小边界校验，可直接删除让应用重建。
- 隐藏时取消待执行及进行中的文件查询，清空结果列表并停止光标闪烁。文件结果最多保留 5,000 项。
- 单实例信号改用注册等待，移除长期占用的线程池等待任务。

## 验证方法与限制

本机两次明确状态的 15 秒采样如下。新后台进程启动后等待 25 秒再采样，使用已有图标缓存：

| 样本 | CPU 增量 | 读 / 写操作 | 读 / 写字节 | 工作集 | 私有内存 |
| --- | --- | --- | --- | --- | --- |
| 修改前、已使用过界面后隐藏 | 0 ms | 0 / 0 | 0 / 0 | 329.7 MiB | 237.6 MiB |
| 0.0.1、启动至后台且尚未显示界面 | 0 ms | 0 / 0 | 0 / 0 | 104.6 MiB | 54.3 MiB |

两者内存状态不同，**不能把差值称为优化节省的百分比**。另一次未隔离启动/界面活动的样本出现 1 次 160 字节写入及约 1.47 秒 CPU，说明“稳态样本为零”并不代表运行期间永远没有 I/O。

缓存与增量检查覆盖：图标跨进程缓存恢复后提取次数为 0；相同数据不重写；新增单项只提取一个图标；删除、目录移动与非递归模式；配置不匹配的缓存被拒绝。实时 Everything 与 Shell 菜单检查独立执行。

进程 I/O 计数不是物理磁盘吞吐量，可能包含文件、管道或设备访问，不能据此推算 SSD 写入寿命。CPU 是采样区间的处理器时间增量。工作集和私有内存包含 .NET/WPF、JIT、托盘、图形及缓存；不得把冷启动后台进程与已显示多次的暖进程直接比较并宣称节省百分比。

本程序不强制清空工作集，不启用周期性 GC，不禁用系统服务。Everything 是独立进程，其索引、资源使用和电池影响不计入 Quickfetch 的进程数据。短时待机采样不能代替电池续航实测。
