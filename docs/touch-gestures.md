# 全局触屏手势

设置 → **触屏手势…**，或右键托盘图标 → **触屏手势设置**。

默认开启全局识别，只要 Quickfetch 在当前用户会话中运行，隐藏到托盘后也能识别。四个滑动动作默认未设置，避免替用户执行操作。**双指右键默认不勾选**，可单独启用。退出 Quickfetch 或取消全局开关后停止监听。进入手势设置时临时暂停识别，保存或取消后恢复。

| 手势 | 起点与方向 | 可配置动作 |
| --- | --- | --- |
| 顶部左半区双指下滑 | 两指都从左半屏顶部边缘向下 | 快捷键 / 启动程序 |
| 顶部右半区双指下滑 | 两指都从右半屏顶部边缘向下 | 快捷键 / 启动程序 |
| 屏幕左侧双指右滑 | 两指都从屏幕左边缘向右 | 快捷键 / 启动程序 |
| 屏幕右侧双指左滑 | 两指都从屏幕右边缘向左 | 快捷键 / 启动程序 |
| 双指靠近轻点 | 勾选双指右键后启用 | 在第一指的起始落点发送一次右击 |

滑动手势要求两指在 180 ms 内落下，起点在对应边缘 32 DIP 内，两指各移动至少 100 DIP，横向偏差不超过主方向位移的 60%，并在 1.4 秒内结束。手指松开后执行一次，三指参与、单指滑动、跨顶部左右分界的手势均不会触发。

右键轻点要求双指距离不超过 80 DIP，各自移动不超过 18 DIP，在 320 ms 内结束。DIP 按映射显示器的缩放比例转换；第一指指最先接收到的落点，两指在同一 HID 帧中到达时按报告顺序处理。

快捷键支持 Ctrl、Alt、Shift、Win 与一个主键组合，以及单独 F1–F24。点击快捷键框后可按组合键，也可从常用预设选择。`Win + S` 直接打开 Quickfetch。某些 Windows 保留组合键可能被系统提前处理，设置时可使用预设。物理修饰键尚未松开时不发送模拟按键，避免破坏键盘状态。

启动程序支持现有 `.exe`、`.lnk`、`.bat`、`.cmd` 文件和可选启动参数；`.lnk` 的参数应在快捷方式自身属性中配置。配置保存在 `%LOCALAPPDATA%\Quickfetch\settings.json`，仅保存配置时写入。

## 显示器与兼容性

- 默认把触屏 HID 坐标映射到主显示器，可在设置中选择触屏所在的显示器。跟随显示器旋转和 DPI；显示设置变化时清空未完成手势。当前支持一块触屏的显示器映射，多块触屏同时使用时不能分别绑定显示器。驱动自定义校准/非标准轴布局仍需实机确认。
- 使用 Windows Raw Input 的 `RIDEV_INPUTSINK` 监听 HID 触屏，不要求管理员权限、UIAccess、额外驱动或 GestureSign。解析标准 Contact ID、Tip Switch、X/Y、Contact Count，支持 parallel / hybrid 报告，设备描述符缓存在内存中。
- **这是并行监听，不会吞掉原始触摸。** 其他应用可能仍响应点击、缩放、滚动，Windows 原有边缘面板也可能出现；不能保证做到 GestureSign 的所有拦截行为。存在冲突时可取消对应动作或关闭全局识别。普通权限的 Quickfetch 无法通过 SendInput 控制管理员窗口，也不在锁屏/UAC 安全桌面运行。
- 手势只覆盖触摸屏，不包含触控板、鼠标或手写笔。休眠、设备拔出和显示设置变化会取消未完成识别；不记录触摸日志，不上传轨迹，不读取其他应用内容。
- 事件驱动、没有轮询定时器；无触摸时不扫描屏幕、不写缓存文件。关闭功能会注销输入监听并结束专用线程。

## 验证范围

自动化检查覆盖四种滑动、首落点、双指时间与距离、第三指/移动/超时取消、混合 HID 帧组装、配置序列化、快捷键和程序校验、全局监听注册与重新注册。还会针对本机支持的触屏描述符在内存中生成 HID 报告，验证原生解析，不向桌面注入测试触摸/点击/按键。

实机仍应检查：屏幕四个边缘的手感、旋转后坐标、双指右键落点、应用和 Windows 边缘动作的冲突。自动化通过不代表已完成所有应用的真实触控兼容性测试。

参考微软文档：[Raw Input 注册](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerrawinputdevices)、[HID 报告解析](https://learn.microsoft.com/en-us/windows-hardware/drivers/hid/interpreting-hid-reports)、[触屏 parallel / hybrid 帧](https://learn.microsoft.com/en-us/windows-hardware/design/component-guidelines/touchscreen-packet-reporting-modes)。功能交互参考 GestureSign 的可配置手势思路，当前实现未复制或引用其源代码。
